## Core Principle

**NO MISTAKES. NO CI MISTAKES.**

Every change must be correct, complete, and pass all CI checks before commit.

## Quick Checklist

### Before Starting
- [ ] Read the backlog item and acceptance criteria
- [ ] Read [AGENTS.md](AGENTS.md) workflow section
- [ ] Read relevant docs (technical-architecture.md, development-setup.md, testing-strategy.md)
- [ ] Plan explicitly: task, files, test strategy

### Before Committing
- [ ] `cargo fmt --check` — formatting correct
- [ ] `cargo build --all` — compiles cleanly
- [ ] `cargo clippy --all-targets` — zero errors
- [ ] `cargo test --all` — all tests pass, zero warnings
- [ ] `cargo deny check` — licenses and security ok
- [ ] `cargo audit` — no vulnerabilities
- [ ] All acceptance criteria verified by tests
- [ ] Implementation documented
- [ ] Commit message is detailed

## Code Quality Standards

### Test First (TDD)
1. Write a failing test for the requirement
2. Write code to make it pass
3. Refactor and verify
4. Repeat for each acceptance criterion

### Tests Must Be
- Comprehensive (happy path, edge cases, errors)
- Isolated (use TempDir, never touch user state)
- Clear (describe what they test)
- Pass with zero warnings

### Production Code Must
- Compile without warnings
- Never use `unwrap()` or `expect()` (add allow to test files only)
- Never use `unsafe`
- Make errors explicit with `Result<T, E>`
- Be well-documented (only comment complex logic)

### Commits Must
- Reference the backlog item (e.g., "B20-01: ...")
- Clearly describe what changed and why
- Verify all acceptance criteria
- Include Co-authored-by trailer
- Never include partial or broken code

## Guardrails

**Protect user state:**
- Use `SF_RUST_STATE_DIR` and temp directories for tests
- Never touch `~/.sf`, `~/.sfdx`, or OS keychain
- Run as `sf-rust` binary, not bare `sf`

**Maintain correctness:**
- Write comprehensive tests before code
- Test edge cases and error paths
- Make errors explicit and testable
- Document design decisions

**Pass all CI:**
- No compiler errors or warnings
- No clippy issues
- No license/security issues
- All tests pass

## Common Mistakes to Avoid

❌ **DO NOT:**
- Commit code with compiler warnings
- Commit code that doesn't pass tests
- Use unwrap/expect in production
- Touch user state in tests
- Skip CI checks
- Assume "we'll fix it later"

✅ **DO:**
- Run all checks locally before pushing
- Use temp directories for test state
- Write tests first
- Make errors explicit
- Document as you code
- Commit complete, working code
