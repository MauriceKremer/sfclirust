# Copilot Agent Instructions for sf-rust

**CORE PRINCIPLE: NO MISTAKES. NO CI MISTAKES.**

This project is a production-grade native Rust reimplementation of Salesforce CLI.
Every change must be correct, complete, and pass all CI checks before commit.

## Before Starting Any Task

1. **Read the backlog item** — Understand all acceptance criteria
2. **Read AGENTS.md** — Understand workflow, guardrails, and where to look
3. **Read relevant docs** — technical-architecture.md, development-setup.md, testing-strategy.md
4. **Plan explicitly** — State the task, files involved, and test strategy

## Code Quality Standards

### No Compiler Errors or Warnings
- All code must compile cleanly: `cargo build --all`
- All tests must pass: `cargo test --all`
- No warnings from clippy: `cargo clippy --all-targets`
- No format issues: `cargo fmt --check`
- No license/security issues: `cargo deny check` and `cargo audit`

### Before Committing
1. Run: `cargo fmt` (fix formatting)
2. Run: `cargo test --all` (all tests pass)
3. Run: `cargo clippy --all-targets` (no warnings)
4. Run: `cargo deny check` (licenses and security ok)
5. Run: `cargo audit` (no vulnerabilities)
6. Verify: All acceptance criteria demonstrated by tests
7. Verify: Implementation documented in IMPLEMENTATION.md or similar

### Test Requirements
- Write tests **first** (TDD approach)
- Tests must be comprehensive: happy path, edge cases, error paths
- Tests must be isolated: use temp directories, mock data, never touch user state
- Add `#![allow(clippy::expect_used, clippy::unwrap_used)]` to test files (workspace forbids these in production code)
- Tests must pass with zero warnings

### Commit Quality
- Clear, detailed commit messages
- Include what changed and why
- Reference backlog items (e.g., "B20-01: ...")
- Confirm all acceptance criteria
- Include Co-authored-by trailer

### CI Pipeline
**All these checks must pass before code is considered done:**
- ✅ format: `cargo fmt --check`
- ✅ clippy: `cargo clippy --all-targets` (0 errors)
- ✅ audit: `cargo audit` (0 vulnerabilities)
- ✅ deny: `cargo deny check` (advisories/bans/licenses/sources ok)
- ✅ tests: All tests passing with zero warnings

## File Organization

- **Source code**: `crates/{sf-cli,sf-core,sf-api}/src/`
- **Tests**: Unit tests in `src/*/tests/` submodules; integration tests in `crates/*/tests/`
- **Documentation**: `docs/backlog/`, `docs/technical-architecture.md`, `docs/testing-strategy.md`
- **Configuration**: `Cargo.toml`, `deny.toml`, `rustfmt.toml`, `clippy.toml`

## Backlog Workflow

1. **Pick** the lowest-numbered unchecked task whose dependencies are complete
2. **Read** all relevant documentation
3. **Inventory** compatibility (if a command) in `docs/compatibility/commands.yaml`
4. **Implement** test-first through the module's public interface
5. **Verify** all acceptance criteria with tests
6. **Update docs** — backlog status, implementation notes, architecture if changed
7. **Commit & push** — detailed message, all CI passing

## Common Pitfalls to Avoid

❌ **DO NOT:**
- Run `sf` (upstream) as the default; use `sf-rust` binary
- Touch user's `~/.sf`, `~/.sfdx`, or OS keychain in tests
- Use `unwrap()` or `expect()` in production code (workspace forbids)
- Use `unsafe` blocks (workspace forbids)
- Accept malformed files silently; make errors explicit
- Skip CI checks or assume they'll pass later
- Commit code with clippy warnings, formatting issues, or test failures
- Leave code partially working; complete or don't commit

✅ **DO:**
- Use temp directories for all test state
- Make errors explicit with descriptive messages
- Write comprehensive tests before code
- Run all CI checks locally before pushing
- Test edge cases and error paths
- Document design decisions in code comments (only when needed)
- Keep commits focused and well-documented
- Verify every acceptance criterion with a test

## Acceptance Criteria Verification

For each backlog item, verify **all** acceptance criteria:
- [ ] Read every requirement in the backlog document
- [ ] Each requirement has at least one test demonstrating it
- [ ] All tests pass with zero warnings
- [ ] No system state touched (temp dirs, mocks only)
- [ ] Errors are explicit and tested
- [ ] Implementation documented
- [ ] All CI checks pass
- [ ] Commit message references the item

## Questions Before Proceeding

If you're unsure:
1. What does the backlog item say the acceptance criteria are?
2. Which existing code provides patterns I should follow?
3. Are there integration points I need to understand?
4. What would go wrong if I skip this test case?
5. Will this CI check fail? (If yes, fix it now, not later)
